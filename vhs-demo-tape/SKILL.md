# VHSデモテープの作成

## 依頼をデモの流れにする

- 依頼から、見せたい機能、起動方法、操作、最後に見せる状態を読み取る。不明点はリポジトリのREADME、実装、既存のVHSファイルから補う。
- 自然文の依頼に加えて、`output=.vhs/quickstart.gif FontSize=24 Width=1440 Theme="Catppuccin Mocha"`のような`key=value`引数を受け付ける。
- コードや既存資料から分からず、デモの内容を大きく左右する情報だけ確認する。
- デモでは実際に動くコマンドと出力を使う。デモのためだけにアプリの機能や振る舞いを変更しない。

## デフォルト設定

引数や自然文に上書き指定がなければ、次をテープの初期設定として使う。デモ内容に応じて`Require`と`Type`のサンプル操作は実際のコマンドに置き換える。

```tape
Output .vhs/demo.gif

Require echo

Set Shell "bash"
Set FontSize 32
Set Width 1200
Set Height 600

Set Theme "nord"

Set Margin 40
Set MarginFill "#6B50FF"
Set BorderRadius 10

Set WindowBar Colorful

Type "echo 'Hello'" Sleep 500ms Enter

Sleep 5s
```

- `output`引数は`Output`のパスを上書きする。
- VHSの`Set`設定は、キー名と値を引数で上書きできる。例: `FontSize=24`, `Width=1440`, `Theme="Catppuccin Mocha"`, `MarginFill="#222222"`。指定されていない設定値は上記のデフォルトを使う。
- 上書き値はVHSのテープ構文に合わせて出力する。指定された値を独自に別の値へ読み替えない。
- 依頼に具体的なデモ操作があれば、サンプルの`Require echo`と`Type "echo 'Hello'" ...`をその操作に置き換える。依頼が単純な動作確認ならサンプルをそのまま使う。

## `.tape`を作成して確認する

- 作業中のリポジトリに既存のVHS設定やデモがあれば、配置場所や見た目を参考にする。新規リポジトリではデフォルトの出力先`.vhs/demo.gif`を使い、`.vhs/`がなければ作成する。
- `.tape`の配置先は依頼で指定された場所を優先する。指定がなければ出力GIFに対応する名前で`.vhs/`に置く。
- 既存ファイルを参照するときは内容を読むだけにし、依頼された出力先以外のテープやGIFは置き換えない。
- 利用可能なら`vhs --version`と`vhs manual`でインストール済みVHSのコマンドと構文を確認する。利用できない場合は[公式VHSドキュメント](https://github.com/charmbracelet/vhs)を参照し、未確認のコマンドを前提にしない。
- 起動手順、作業ディレクトリ、必要なコマンドを明確にし、依存プログラムが分かる場合は`Require`を使う。再現できるコマンドを優先する。
- `Wait`がインストール済みバージョンで使える場合は、画面の状態を待つ用途に使う。遷移や出力を見せる間は`Sleep`を必要な長さにし、デモが間延びしないようにする。
- `Hide`/`Show`は見せる必要のない起動時のノイズを隠す場合だけ使い、操作と結果のつながりは残す。
- `vhs validate`はテープ構文の確認であり、録画環境の起動確認ではない。通常はsandbox内でレンダリングを試す。
- レンダリングが起動段階で長時間止まり、テープのコマンド出力やGIFが生成されない場合は、sandbox内のプロセス・ブラウザー・localhost通信制限の可能性を考える。すでに同じ環境で再現済みなら、失敗するレンダリングを繰り返さない。
- sandbox外での再試行が必要な場合は、理由（VHSが補助端末やブラウザーを起動すること）と対象テープを明示し、ツールの承認付き権限昇格で`vhs <対象.tape>`だけを実行する。承認前に実行せず、sandbox設定を恒久的に緩めたり、無関係なコマンドまで昇格したりしない。承認されない／利用できない場合はテープを残し、GIFは未生成と報告する。
- VHSとデモの依存関係がすでに利用できる場合はテープをレンダリングし、ファイルの生成と意図した内容を確認する。画像を確認できる環境ならGIFの見た目も確認する。依存ツールのインストールが必要なら試みず、不足しているものを報告する。
- 最後に作成・変更したファイル、レンダリング結果、実行コマンドを簡潔に伝える。
